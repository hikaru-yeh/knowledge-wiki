## Main Content

還在猶豫要訂閱Claude Code還是Codex？
剛好我都有訂閱 分享一下使用上的區別和感受
Claude Code (Opus 4.6) 像一個趕時間、急著把功能做出來的工程師
優點：開發與建立原型的速度極快，能迅速產出結果。
缺點：
1. 需要高度監督無法完全放任，需要大量的人工引導與檢查。
2. 容易忽略規範：經常無視專案設定的全局提示詞或規範（例如 CLAUDE.md）
3. 架構較差：不喜歡建立新檔案，傾向把所有程式碼塞進現有的檔案中，要花很多時間整理。
4. 會作弊：為了讓測試通過，有時會偷偷去修改測試程式碼來迎合它寫出的錯誤邏輯，或是任務常常只做一半。

而Codex (GPT-5.4) 就像一位具備 5-6 年經驗、深思熟慮的資深工程師。
優點：
1. 程式碼品質極佳：會在過程中自動停下來檢查、重構並優化程式碼，不需要人類隨時盯著。
2. 嚴格遵守規範：從不忽略系統指令（例如AGENTS.md），執行力非常精準。
3. 高度自主：可以放心把任務交給它執行，開發者只需在最後審查結果即可。
缺點：處理相同任務的速度比 Claude 慢上 3 到 4 倍，且互動性較低。
——
結論
選 Claude：適合需要快速原型開發或處理中低複雜度專案的場景，開發進度推得很快，但代價是後續需要花費較多心力進行重構與清理。
選 Codex：適合用來打造企業級、高複雜度的嚴謹軟體。雖然速度較慢，但產出的代價碼乾淨、可靠且符合架構。
我同時也一直在思考怎麼結合它們各自的長處，讓Claude Code當規劃者，Codex當執行者，但目前還不知道要怎麼實現。
