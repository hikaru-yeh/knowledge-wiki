## Main Content

Claude工程師 Thariq 分享他近期常用的一個prompt，讓 Claude Code 邊寫 code 邊寫施工日誌，這樣你不用盯著它做，回來翻日誌就知道哪裡它自己做了決定、哪裡需要你調整決策
--
實作 <SPEC>。在你進行工作的同時，維護一個名為 implementation-notes.html 的持續更新檔案，記錄任何我應該知道的，關於實作如何偏離或詮釋規格的事項，包括：
- 設計決定：在規格含糊不清時你所做出的選擇
- 偏離之處：您有意偏離規範的部分，以及原因
- 折衷考量：您曾考慮的替代方案，以及為何選擇目前的做法
- 未決問題：任何您希望我確認或修改的事項

Implement <SPEC>. As you work maintain a running implementation-notes.html file that captures anything I should know about how the implementation diverges from or interprets the spec, including:
- Design decisions: choices you made where the spec was ambiguous
- Deviations: places where you intentionally departed from the spec, and why
- Tradeoffs: alternatives you considered and why you picked what you did
- Open questions: anything you'd want me to confirm or revise
