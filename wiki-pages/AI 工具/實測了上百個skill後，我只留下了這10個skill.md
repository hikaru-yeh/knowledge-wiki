## Main Content

與其列清單，我直接按使用頻率告訴你哪些真的在用。 天天開著的： Superpowers、Planning with Files、Ralph Loop 寫專案時常駐： Code Review、Code Simplifier、Webapp Testing 需要才裝： UI UX Pro Max、MCP Builder、PPTX、Skill Creator 第一檔：少了它們我不會寫 code 了 Superpowers 這個 Skill 徹底改變了我用 Claude Code 的方式。 以前我都是直接把需求丟給 Claude 讓它寫。能跑是能跑，但常常跑歪，改來改去浪費超多時間。 裝了 Superpowers 之後，我養成了一個新習慣：每次動工前先跑一遍 brainstorming。 Claude 會反過來問你問題——「你怎麼處理併發？」「資料庫選哪個？」「這個 API 需要冪等嗎？」問完一圈，它會把討論結果存成設計文件放在本地。 聽起來多了一個步驟，但這一步幫我擋掉了超多次重工。有些問題你自己沒想到，Claude 替你想到了。 Superpowers 裡還有 TDD 模式。開了之後 Claude 一定要先寫測試再寫 code，測試沒過就不算完。Claude 很愛寫完跟你說「應該沒問題」，這個模式直接堵死它偷懶的路。 ⚠️ Superpowers 有 20 幾個子 Skill，千萬別全開。我只用 brainstorming 和 TDD，其他按需載入。全開會把上下文吃光。 Planning with Files 這個解決了我被坑過無數次的問題：Claude 做到一半失憶。 你有沒有遇過？一個複雜任務聊了半小時，Claude 突然說「好，我們開始吧」，然後把之前做過的事重來一遍。原因是對話太長、上下文被壓縮，之前的規劃全不見了。 Planning with Files 的做法很聰明：別把計畫存在腦子裡（上下文），存到檔案裡。Claude 動手前會先建一個計畫檔，每完成一步就在裡面打勾。就算上下文清空了，重新讀一下檔案就能接著做。 這個邏輯跟 Manus 很像。Manus 做長任務為什麼穩？因為所有中間狀態都有落檔。 Ralph Loop 我幫這個取了個外號：監工 Skill。 你一定體驗過 Claude 的「摸魚」模式。寫到一半突然說「基礎框架已經搭好了，你可以在這個基礎上繼續完善」。翻譯一下就是：活沒幹完，我先下班了。 Ralph Loop 透過一個 Hook 攔截 Claude 的退出動作。它要退出的時候 Hook 會檢查：你說的完成條件達到了嗎？沒達到？回去繼續寫。 我用它完成過一個 CRUD 模組，設了條件「所有 API 測試通過 ＋ README 寫完才算結束」。Claude 中間想收工三次，都被塞回去了，最後確實把事情做完了。 💡 完成條件一定要寫具體。「做完使用者模組」這種說法等於沒說，Claude 隨時可以說服自己已經完成了。要寫成「登入註冊 API 可用 ＋ 單元測試覆蓋率 80% 以上 ＋ README 包含 API 文件」，它才沒辦法混水摸魚。 第二檔：寫 code 的時候常駐 Code Review 讓一個 AI 從頭看到尾，效果其實普普，因為它什麼都想挑。「這裡可能有效能問題」「這個變數名不夠清楚」「建議加個註解」——一堆正確但沒用的廢話。 Code Review 這個 Plugin 換了個思路：拆成多個 Agent 各管各的。一個看邏輯 bug，一個看資安問題，一個看風格規範。每個 Agent 的回饋都附一個信心分數，最後只顯示高分的。 我在一個 200 行的 PR 上試過，一般 Claude 給了 17 條建議，Code Review 過濾後剩 5 條。這 5 條裡有 3 條是真的需要改的。效率差很多。 ⚠️ Token 消耗要注意，多 Agent 並行跑，一次 review 的花費可能比寫 code 還高。小 PR 隨便用，大 PR 記得先拆。 Code Simplifier 寫 code 有個通病：能跑就不想再碰了。 但回頭看自己的 code，常常會發現三段一模一樣的 try-catch，或者一堆可以合併的 if-else。Code Simplifier 專門處理這個：不動功能，只精簡結構。 有一次我寫了一個資料清理腳本，Code Simplifier 跑完把三段重複的例外處理合成了一個工具函式，整個檔案少了 40 行。這種事我自己肯定懶得做。 Webapp Testing 如果你做前端，這個配合 Claude 寫頁面根本無敵。 流程是這樣：Claude 幫你生了一個頁面，你讓它跑 Webapp Testing，它會自己寫 Playwright 測試腳本、開瀏覽器、跑一遍、截圖給你看結果。有 bug 它還會自動修。 我現在的工作流是：寫前端 → 跑 Webapp Testing → 看截圖 → 讓它修。整個過程不用自己手動開瀏覽器。 第三檔：需要才裝，不常駐 UI UX Pro Max Claude 寫前端有個通病：紫色漸層 ＋ 圓角卡片 ＋ 置中，千篇一律的「AI 美感」。 這個 Skill 內建 67 種設計風格和 161 套配色。我拿它做過一個 SaaS 後台，選了 Bento Grid 風格，出來的東西確實看不出 AI 的味道。支援 React、Vue、SwiftUI、Flutter，不限 Web。 不常駐的原因：不是每次寫 code 都需要做 UI，需要的時候再開就好。 MCP Builder 想自己做 MCP Server 但不知道從哪開始？這個幫你拆成四步：搞清楚 API → 設計介面 → 寫 code → 跑測試。 最大的價值是它會替你想到很多邊界情境。直接讓 Claude 寫 MCP Server，它常常忘了做流量限制和 token 更新。走 MCP Builder 的流程，這些它會主動問你要不要加。 PPTX 工程師做簡報的痛苦不用我解釋。 這個 Skill 可以直接生成 .pptx 檔，帶母版和圖表。生成品質說實話，直接拿去報告是不行的。但當初稿用已經夠了，至少不用對著空白頁發呆半小時。 Skill Creator 用來造 Skill 的 Skill，很 meta。 Anthropic 官方出的。最值得提的是它附了 eval 測試框架，你可以幫自己寫的 Skill 做 A/B 測試，量化「裝了這個 Skill 之後 Claude 到底好了多少」。 前面 9 個用完覺得不夠？那就自己造一個。 ⚠️ 我踩過的坑 別當收藏控。 Skill 的描述符會吃上下文空間。裝 10 個，光描述符可能就吃掉幾千 token。Claude 還沒開始做事就先讀了一堆說明書，當然會變鈍。 跟專案綁定的 Skill 放專案目錄裡。 提交到 Git，團隊都能用，也不會污染其他專案的上下文。 用完記得關。 不是每個 Skill 都需要一直開著。我現在常駐只有 3 個，其他的用到再打開。 10 個夠不夠？ 對我目前的工作流來說，這 10 個已經涵蓋了 90% 的場景。 與其一直追新裝一堆用不上的，不如把手邊這幾個用熟了。
