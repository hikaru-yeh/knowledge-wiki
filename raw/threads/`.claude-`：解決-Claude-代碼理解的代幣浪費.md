I tracked my Claude Code token usage across 6 projects for 3 weeks.
The finding: 60–70% of every session goes to orientation — not writing code. Claude re-learns your codebase from scratch every single time you open a session.
Here's the full breakdown and how to fix it.

The numbers:
First session on a new codebase → 12,000 tokens on orientation, 4,000 on actual work.
Return session after a week → 8,000 orientation, 6,000 work.
Return session with .claude/ set up → 1,500 orientation, 7,000 work.
You're not paying for code generation. You're paying for code comprehension. Over and over on a codebase that hasn't changed.

I tried the obvious fixes. Better prompts, pasting context manually, Claude's built-in memory.
None of it solved the real problem. The issue is structural — Claude starts every session blind because nothing in the project tells it what it needs to know.
The fix has to live in the repo itself.

The solution is a .claude/ directory in your project root. Four pieces:
CODEBASE.md — a ~2,000 token map of your whole project. Replaces 30–40k tokens of blind exploration with one file Claude reads immediately.
skills/ — task instructions for your specific codebase. How to add an API route in this project, with these imports, these conventions. Written once, reused every session.
memory/ — three files: architecture, conventions, and decisions. The decisions file is the underrated one.

It stops Claude re-litigating technology choices you've already made.
patterns/ — reference implementations from your actual production code, so Claude doesn't guess from training data.

One thing that surprised me: newer models seem to make this gap larger, not smaller. They explore more thoroughly and reason harder before committing — which is good for code quality, but burns more tokens on orientation when there's no structure to anchor them.
The problem doesn't self-correct with model updates.
