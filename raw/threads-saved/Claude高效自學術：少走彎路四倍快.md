100 次失敗後，我終於搞懂了「自學」這件事的本質。
剛開始學 Python 的時候，我的方式是找一門線上課程，然後從第一章開始看。
看完第一章覺得懂了，看完第二章覺得還好，看到第三章開始跳著看，看到第五章完全不知道自己在幹嘛，然後課程就這樣爛尾了。
這個劇本我重複了大概四、五次，換過 Python、換過 Excel、換過影片剪輯，每次都是同樣的結局。
我一直以為是自己不夠自律，後來才發現，問題根本不是自律，而是我的學習方式從一開始就錯了。
後來我開始把 Claude 當成我的私人家教，不是叫它幫我找課程，而是直接跟它說「我想學 XX，幫我設計一個學習路徑」，才發現自學這件事可以差這麼多。

▋方法一：不要找課程，先請 Claude 幫你畫「學習地圖」
自學最容易卡住的地方，不是不夠努力，而是你根本不知道這個技能的全貌長什麼樣子。
你不知道哪些東西是核心、哪些是進階、哪些是你這個目標根本不需要學的。
所以你從第一章開始學，其實是在學一個你不知道終點在哪的迷宮。
換一個方式，直接問 Claude：「我想學 Python，目的是做資料整理和自動化報表，不是要成為工程師，幫我列出我真正需要學的核心概念，以及我可以跳過的部分。」
Claude 給出來的學習地圖，會讓你一眼看清楚「我需要的只有這幾塊」，而不是一門課裡面的全部內容。
這樣你的學習效率，從一開始就不一樣了。
我用這個方式重新學 Python，從零到可以自己寫出自動化報表的腳本，花了三週，比之前跟著課程學了三個月還沒成果，差了將近 4 倍。

▋方法二：學完一個概念，馬上請 Claude「出題考你」
這是我覺得最多人忽略、但效果最明顯的方法。
很多人學完一個東西，會覺得「我懂了」，然後繼續往下學。
但老實說，「看懂」和「真的懂」是兩件完全不同的事。
你以為你懂，是因為你在看別人的解釋，那個解釋是順的，所以你的腦袋跟著順。
但當你要自己解釋、或是自己用的時候，才會發現哪裡其實沒懂。
所以每次學完一個概念，我會直接跟 Claude 說：「我剛學完 XX 的概念，請用 3 個不同難度的題目考我，從簡單到有點挑戰性，我答完之後你再告訴我哪裡理解有偏差。」
這個方式讓我的學習從「輸入」變成「輸入加輸出」，理解的深度完全不同。
像是你可以說：「我剛學完 Excel 的 VLOOKUP，請出 3 題情境題考我，不要只考語法，要考我什麼情況下應該用這個函數。」
這樣問出來的題目，會逼你真的去思考，而不是背公式。

▋方法三：遇到卡住的地方，請 Claude 用「你最熟悉的東西」來解釋
這個方法是我從一個意外的經驗裡發現的。
有一次我在學資料庫的概念，JOIN 這個操作一直看不懂，看了三篇文章還是霧煞煞。
後來我直接跟 Claude 說：「我完全看不懂資料庫的 JOIN 是什麼意思，我比較熟悉 Excel，可以用 Excel 的邏輯來解釋給我聽嗎？」
它給我的解釋是：「JOIN 就像是你在 Excel 裡面用 VLOOKUP 把兩張表的資料合在一起，只是資料庫可以同時處理更大量的資料。」
那一句話，讓我五秒內就懂了一個卡了我三天的概念。
這讓我意識到，學習卡關的時候，問題通常不是你不夠聰明，而是解釋的語言跟你的背景不匹配，只要換一個你熟悉的框架，很多東西其實一點都不難。

以上這 3 個方法，是我在自學這條路上最受用的心得。
說到底，學習的關鍵不是你花了多少時間，而是你有沒有在對的地方用力。
只要下次想學一個新技能，先請 Claude 幫你畫出學習地圖，搞清楚你真正需要學的是哪些，你會發現學習這件事從來沒有你想的那麼難。
